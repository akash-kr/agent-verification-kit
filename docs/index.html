Four ways an agent fakes a green build

Each one leaves the suite green. Each refusal below is the tool's real output.

Every refusal says how to fix it. If a skip really is right, the owner grants that one finding by its id in .guard-allow. A comment on the line is not enough, and a key in history can't be granted at all.

Set it up in a repo

It's git hooks, a Python script and a CI workflow. Claude Code, Codex, Cursor, Gemini and people all push through the same checks.

  1. Install it into your repo.
    git clone https://github.com/akash-kr/receipts ~/receipts
~/receipts/scripts/setup /path/to/your/repo --github
  2. Point agent-check.toml at your test command and test folder.

    It starts as test = "python -m pytest -q" and tests = "tests/". Change both to what your repo runs.

  3. Tell your agents the rules.

    Paste docs/VERIFICATION.md into your AGENTS.md or CLAUDE.md.

  4. Watch for a week, then switch on.

    The guard starts in observe: it logs what it would refuse. Read the log, then set guard = "enforce". A key in history is refused from day one.

  5. When a push is refused, fix the code.

    Only the owner grants a finding, through .guard-allow. Protect it with CODEOWNERS and branch protection.

The guard is one part of the kit. The rest makes an agent prove a change works with a real run tied to the commit, seals the tests that hold your rules, and requires a bug test to fail before the fix. Read the README.

What it won't catch

  • Tests switched off in config: -k 'not x' in addopts, collect_ignore, a load_tests that returns nothing.
  • A rename it doesn't know (test_x to tst_x), or a skip decorator it doesn't know.
  • Loosened or removed assertions. They're listed at push, not refused.
  • Local hooks can be bypassed with --no-verify. CI is the check that counts.
  • Without branch protection, an agent can write its own grant. Use CODEOWNERS on .guard-allow.
